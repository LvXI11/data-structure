# 递归 + 树学习法总结

## 一、写递归的"万能三问"（每次动笔前问）

1. **空的情况返回什么？**（出口，必须能停）
2. **非空时，结果 = "自己贡献的" + 什么"更小的同构问题"？**
3. **更小的问题，能不能让函数自己算？**（信任它）

对应万能骨架：

```c
int f(Tree* T){
    if(T==NULL) return 0;                        // ① 出口
    return [自己贡献] + f(T->lchild) [+ f(T->rchild)];   // ②③
}
```

## 二、"信任原则"（递归唯一的心法）

- **不要人肉展开**——展开超过 3-5 步必然迷路，迷路是正常的，不是你不聪明
- 人肉展开只用于**调试**（走 3-5 步看状态错在哪），不用于**理解**
- 理解递归 = **验证出口 + 信任递推**（数学归纳法思维）：出口对 + 单层逻辑对 → 整棵树都对
- 每个函数**只回答一个问题**，每个节点**只被问一次**

## 三、三个函数的骨架对比（会一个就会三个）

| 函数 | 空返回 | 自己贡献 | 组合 |
|---|---|---|---|
| 节点数 | 0 | 1 | `1 + 左 + 右` |
| 树高 | 0 | 1（层） | `1 + max(左, 右)` |
| 叶子数 | 0 | 我是叶子就返回 1 | `左 + 右` |

## 四、学新概念（非递归遍历这类）的流程

1. **第一次接触的概念先看视频**（建立心理模型），但看完必须合上
2. **"抄三遍"把别人的代码变成自己的**：
   - 第一遍：照抄，跑通
   - 第二遍：合上，凭记忆写（默写）
   - 第三遍：**改它**（中序→前序挪一行 printf）——能改 = 真懂
3. **验证靠"标准答案对照"**：你的图/手推结果当测试用例，输出不一致就是哪里错了
4. **卡壳流程**：憋 10 分钟 → 画图/打印中间值 → 带着"卡在哪"问 AI
