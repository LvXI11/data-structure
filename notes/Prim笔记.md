# Prim 最小生成树笔记

> 2026-09-16 整理。**重点：`lowcost` / `adjvex` 这两个辅助数组到底在干什么。**
> 配套代码：`rewrite/graph/prim/main.c`；测试图：6 顶点 10 边，总权 15。

---

## 一、模型：铺电网

- 已进树的顶点 = **已经通电的城市**
- 其余顶点 = **还没通电的**

每一轮只做一件事：

> **找一个"接线最便宜"的没通电城市，把它接通。**

---

## 二、两个辅助数组（核心，这节最重要）

### 初始状态（树里只有起点 u0 = v0）

```
下标 i :     0     1     2     3     4     5
顶点   :    v0    v1    v2    v3    v4    v5      ← i 就是顶点编号
──────────────────────────────────────────────
lowcost:     0     6     1     5    INF   INF      ← = arcs[0][i]
adjvex :     0     0     0     0     0     0       ← 都是 u0
visited:     1     0     0     0     0     0       ← 只有 v0 进树
```

**为什么这么初始化？** 因为一开始树里**只有 `u0` 一个顶点**，所以"每个顶点到树的距离"就等于"每个顶点到 `u0` 的距离" —— 正好就是邻接矩阵里 `u0` 那一行。

### 第 1 轮（v2 进树）之后

```
下标 i :     0     1     2     3     4     5
──────────────────────────────────────────────
lowcost:     0     5     1     5     6     4
adjvex :     0     2     0     0     2     2
```

### 两个数组各存什么

| 数组 | 下标 `i` 代表 | 存什么 |
|---|---|---|
| `lowcost[i]` | **顶点编号 i** | 顶点 `i` 到「已进树区域」**最短的那条候选边的长度** |
| `adjvex[i]` | **顶点编号 i** | 那条候选边**是从树里的哪个顶点（编号）接过来的** |

**读法（一格就是一个顶点，横着读一遍就是每个顶点的情况）：**

| 格子 | 读作 |
|---|---|
| `lowcost[1] = 5` | "顶点 v1 到树，最近是 5" |
| `adjvex[1] = 2` | "这 5 是从 **v2** 接过来的" |
| 两格合起来 | 候选边 = **v2 — v1，权 5** |

> ⚠️ **`adjvex` 存的是「顶点编号」，不是「顶点名」。** 证据：代码里写的是 `G->vertex[adjvex[k]]` —— `adjvex[k]` 是当下标用的。要取名字，得再套一层 `G->vertex[...]`。

### 三个容易混的地方

1. **下标不是"进树的顺序"** —— 数组按顶点编号固定排列。`v2` 是最先被选中的，但它在**下标 2** 那一格。
2. **数组长度 = 顶点数，不是边数** —— `lowcost[MAXV]`、`adjvex[MAXV]`，**一个顶点一格**。6 个顶点 10 条边，也只占 6 格。
3. **已进树的顶点那一格还在，但不参与** —— `v0` 的 `lowcost[0]=0`、`adjvex[0]=0`，永远不会被选，因为两个循环里都有 `!visited[j]` 挡着。

### 为什么必须两个数组

> **一条边 = 两个端点 + 一个长度。三个数。**

选中顶点 `k` 之后，手里正好有三个数：

| 变量 | 是什么 |
|---|---|
| `k` | 新进树的顶点（**一端**） |
| `adjvex[k]` | 树里的那个顶点（**另一端**） |
| `lowcost[k]` | 这条边的**长度** |

合起来就是一条边：`v2 — v5，权 4`。

**`lowcost[k]` 只说"多长"，说不出"连谁"** —— 所以必须有 `adjvex` 补上另一个端点。

对应代码里那一行：

```c
printf("边 %s - %s 权 %d\n", G->vertex[adjvex[k]], G->vertex[k], lowcost[k]);
//                              ↑ 树里那一端      ↑ 新顶点        ↑ 长度
```

### 为什么下标是"顶点"而不是"边"

**因为 Prim 的决策单位是"顶点"。** 每一轮问的是"下一个把哪个顶点拉进树"，答案是一个**顶点编号**。

**所以记账本天然是"一个顶点一格"—— 数组的形状，反映了算法的决策单位。**

> 对比：**Kruskal 的决策单位是"边"**，所以它不用这种数组，而需要一个**边集数组**（一格存一条边 `(u,v,w)`）。同一个图，换个算法，记账本的形状就变了。

## 三、两个动作：**选** 和 **更新**

**这两个动作完全不同，别混：**

| 动作 | 干什么 | 改数据吗 |
|---|---|---|
| **选** | 在**当前的候选值**里，挑出 `lowcost` 最小的那个顶点 → 得到 `k` | **不改**，只是"挑" |
| **更新** | **修正候选值本身** —— 发现更短的线就把 `lowcost` 改小 | **改** |

> **让 `lowcost` 里的数字越来越准的是「更新」，不是「选」。**
> 「选」永远选不到一个 `INF` —— 一个顶点能从 `INF` 变成有限值，全靠「更新」。

### 关键规律（这一条必须记住）

> **`lowcost` 变一格，`adjvex` 就跟着变一格 —— 两行永远同步。**

**为什么？** 因为"价钱变了"的意思是「**这条线换了**」。换了线，**线的另一端自然也变了**。

```c
lowcost[j] = G->arcs[k][j];      // 换线
adjvex[j]  = k;                  // 来源跟着换
```

**只写第一行 → 长度和端点对不上 → 打印出来的边是假的。**

### 例：第 1 轮（k=2）的"更新"逐格展开

`v2` 那一行是 `[1, 5, 0, 5, 6, 4]`，`j` 从 0 走到 5：

| `j` | `visited[j]` | `arcs[2][j]` | 原 `lowcost[j]` | 判断 | 动作 |
|---|---|---|---|---|---|
| 0 | **1** | 1 | 0 | 已进树 → 跳过 | — |
| **1** | 0 | **5** | **6** | `5 < 6` ✓ | `lowcost[1]=5`，`adjvex[1]=2` |
| 2 | **1** | 0 | 1 | 已进树 → 跳过 | — |
| 3 | 0 | 5 | 5 | `5 < 5` ✗ | **不变**（来源仍是 v0） |
| **4** | 0 | **6** | **INF** | `6 < INF` ✓ | `lowcost[4]=6`，`adjvex[4]=2` |
| **5** | 0 | **4** | **INF** | `4 < INF` ✓ | `lowcost[5]=4`，`adjvex[5]=2` |

**念一遍：**
- `j=1` → "从 v2 到 v1 要 5，原来记的是 6（从 v0 走）。**更便宜 → 换！**"
- `j=3` → "从 v2 到 v3 也是 5，原来也是 5。**一样贵 → 不换**"（所以 `adjvex[3]` 保持 0）
- `j=4`、`j=5` → **从"不可达(INF)"变成"可达"** —— 这是最关键的一次更新

## 四、完整五轮手推（对着这张表，Prim 就全在眼前了）

| 轮 | 选出的 `k` | 打印的边 | 权 | 累计 | 更新做了什么 |
|---|---|---|---|---|---|
| — | — | — | — | 0 | 初始：`lowcost=[0,6,1,5,∞,∞]`，`adjvex` 全 0 |
| 1 | **v2** | `v0—v2` | 1 | **1** | v1: 6→**5**；v4: ∞→**6**；v5: ∞→**4** |
| 2 | **v5** | `v2—v5` | 4 | **5** | v3: 5→**2**；v4 保持 6 |
| 3 | **v3** | `v5—v3` | 2 | **7** | 无变化（v3 的邻居都进树了） |
| 4 | **v1** | `v2—v1` | 5 | **12** | v4: 6→**3** |
| 5 | **v4** | `v1—v4` | 3 | **15** | 没有未进树的顶点了，结束 |

**每轮结束后的两行数组：**

| 轮 | `lowcost`（v0..v5） | `adjvex`（v0..v5） |
|---|---|---|
| 初始 | 0, 6, 1, 5, ∞, ∞ | 0, 0, 0, 0, 0, 0 |
| 1 后 | 0, **5**, 1, 5, **6**, **4** | 0, **2**, 0, 0, **2**, **2** |
| 2 后 | 0, 5, 1, **2**, 6, 4 | 0, 2, 0, **5**, 2, 2 |
| 3 后 | 0, 5, 1, 2, 6, 4 | 0, 2, 0, 5, 2, 2 |
| 4 后 | 0, 5, 1, 2, **3**, 4 | 0, 2, 0, 5, **1**, 2 |
| 5 后 | 结束 | 结束 |

**注意第 4 轮那次更新**：`v4` 从 6 变成 3 —— 因为 `v1` 进树了，`v1—v4` 只要 3，比原来的 `v2—v4`（6）便宜。**这就是"树长大了，旧候选边过时了"的具体例子。**

**最终答案（和程序输出逐字一致）：**

```
边 v0 - v2  权 1
边 v2 - v5  权 4
边 v5 - v3  权 2
边 v2 - v1  权 5
边 v1 - v4  权 3
最小生成树总权值 = 15
```

## 五、「更新」为什么必须有

**不更新 → 树长不大。**

反例（把"更新"整段去掉）：

```
初始：lowcost = [0, 6, 1, 5, ∞, ∞]

第1轮 候选 v1(6) v2(1) v3(5) v4(∞) v5(∞)  → 选 v2(1)  ✔ 加边 v0-v2
第2轮 候选 v1(6) v3(5) v4(∞) v5(∞)        → 选 v3(5)  ✔ 加边 v0-v3
第3轮 候选 v1(6) v4(∞) v5(∞)              → 选 v1(6)  ✔ 加边 v0-v1
第4轮 候选 v4(∞) v5(∞)                    → 全是 ∞，卡死 ✘
```

**结果：树里只有 4 个顶点，v4 和 v5 永远进不来 —— 根本不是生成树。**

**原因**：`v4`、`v5` 一开始和 `v0` 不直接相连，`lowcost` 是 `∞`。**只有靠"更新"（v2 进树时发现 v2 能连到它们），它们才有机会进来。**

> **"更新"就是树的扩张能力。不更新，树就长不大。**

## 六、代码骨架

```c
void prim(ALGraph* G, int u0){
    int lowcost[MAXV];
    int adjvex[MAXV];
    int visited[MAXV] = {0};          // 必须 = {0}！
    int weight_sum = 0;

    // ① 初始化：树里只有 u0，所以用 u0 那一行填 lowcost
    //    （这只是初始候选值，后面靠"更新"逐步改准）
    for(int i=0;i<G->vexnum;i++){
        lowcost[i] = G->arcs[u0][i];  // 注意是 arcs，不是 vertex
        adjvex[i]  = u0;              // 来源都是 u0（编号）
    }
    lowcost[u0] = 0;
    visited[u0] = 1;                  // 起点进树

    // ② 收剩下的 n-1 个顶点
    for(int t=0;t<G->vexnum-1;t++){
        int min = INF;                // 每轮都要重置
        int k = -1;

        // ③ 选：未进树的顶点里 lowcost 最小的（k 是顶点编号，不是边）
        for(int j=0;j<G->vexnum;j++){
            if(!visited[j] && lowcost[j] < min){ min = lowcost[j]; k = j; }
        }
        if(k == -1){ printf("图不连通\n"); return; }

        // ④ 加边 + 累加 + 登记入树（三件事同级）
        printf("边 %s - %s 权 %d\n",
               G->vertex[adjvex[k]], G->vertex[k], lowcost[k]);
        weight_sum += lowcost[k];
        visited[k] = 1;               // ← 最容易漏的一行！

        // ⑤ 更新：扫 k 那一行，更短就换（两行必须成对改）
        for(int j=0;j<G->vexnum;j++){
            if(!visited[j] && G->arcs[k][j] < lowcost[j]){
                lowcost[j] = G->arcs[k][j];
                adjvex[j]  = k;
            }
        }
    }
    printf("最小生成树总权值 = %d\n", weight_sum);
}
```

## 七、复杂度（面试必问）

**用邻接矩阵的 Prim：`O(n²)`**（n = 顶点数）

怎么算出来的：

| 部分 | 次数 |
|---|---|
| 外层循环 | `n-1` 轮 |
| 每轮"选" | 扫 n 个顶点 → `O(n)` |
| 每轮"更新" | 扫矩阵的一行 → `O(n)` |
| **合计** | `(n-1) × 2n` = **`O(n²)`** |

**关键：复杂度和边数 `e` 无关，只和顶点数 `n` 有关。**

所以：

| 图的类型 | 适合的版本 |
|---|---|
| **稠密图**（e 接近 n²） | **矩阵版 Prim `O(n²)`** —— 正好 |
| **稀疏图**（e 远小于 n²） | 用**堆优化版 Prim `O(e log n)`**（超出当前范围，知道有这回事就行） |

## 八、三个值得知道的性质

### ① 起点可以随便选

从 v0 开始和从 v3 开始，**总权值都是 15**。因为最小生成树的**权值是唯一的**。

（但**选的边可能不同** —— 当图里有相同权值的边时，最小生成树可能不止一棵。）

### ② 权值唯一，树不一定唯一

你的测试图里 `权 5` 出现 3 次、`权 6` 出现 3 次 —— 所以换起点可能选出不同的边，但**总权值恒定 15**。

### ③ 为什么"每轮选最近的"是对的（贪心为什么可行）

每一轮选的那条边，是「**连接『树』和『树外』的所有边里最短的那条**」。

直觉：**要让树长大，就必须有一条边跨出当前区域。跨出去最便宜的那条，一定不会亏。**

严格说这叫**切割性质**（cut property）：连接"树"和"树外"的最短边，**一定属于某棵最小生成树**。所以每轮拿它都不会错。

## 九、易错点（全是"静默错误"，`-Wall` 不报）

| 坑 | 后果 |
|---|---|
| 漏 `visited[k]=1` | 每轮选同一个人 → 输出五行一模一样、总权值恒为 0 |
| `for(int t;` 漏 `=0` | 循环一次都不跑 → "更新"完全没发生 |
| 初始化用 `G->arcnum` | 那时还没读入，是垃圾值 → 矩阵没被初始化成 `INF` |
| 忘 `if(k==-1)` | 图不连通时 `lowcost[-1]` 数组越界 |
| 无边格子填 `0` 而不是 `INF` | 0 会被当成"距离 0 的边"，优先选它 → 结果全错 |
| 更新时只改 `lowcost` 不改 `adjvex` | 长度和端点对不上 → 打印的边是假的 |

## 十、和 Dijkstra 的关系（9/18 会用到）

「更新」这一步在算法里叫「**松弛**」（relaxation）：发现一条更短的路，把记录改小。

**Dijkstra 做的是同一个动作**，数组和循环结构完全一样，唯一区别在**比较的东西**：

| | 比较的是 |
|---|---|
| **Prim** | "从树到 j 的**一条边**"有多长 |
| **Dijkstra** | "从起点到 j 的**整条路径**"有多长 |

**今天把 Prim 的更新吃透，Dijkstra 就省一半力。**
